# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A Create React App (React 19, `react-scripts` 5) single-page application, deployed to AWS as static files: a private S3 bucket behind CloudFront. Infrastructure is managed with Terraform in `us-east-1`. GitHub Actions builds the app and deploys it on every push to `main`, authenticating to AWS with OIDC (no stored keys).

Fork: `agulaldi/my-react-app`. AWS account: `373550664081`.

## Architecture

```
src/                 # React source (App.js, index.js, tests in src/tests/)
public/              # static files copied into the build (index.html, icons, manifest)
build/               # output of `npm run build` (git-ignored); this is what gets deployed
terraform/           # S3 + CloudFront + GitHub OIDC deploy role (generated by /scaffold-terraform)
.github/workflows/   # deploy.yml: test, build, sync build/ to S3, invalidate CloudFront
.claude/             # skills, subagents, hooks and settings for Claude Code
.mcp.json            # Terraform and AWS MCP servers
```

Request flow: browser → CloudFront (HTTPS, security headers) → S3 (private, Origin Access Control). CloudFront returns `/index.html` for 403 and 404 so client-side routes work.

## Build and Test

```bash
npm ci                                # install exact versions from package-lock.json
npm run build                         # production build into build/
CI=true npm test -- --watchAll=false  # run the Jest tests once (src/tests/)
npm start                             # local dev server on http://localhost:3000
```

The tests check the texts "Welcome to My React App" and "This app is running on Nginx!" in `App.js`; change them together.

## Deployment Workflow

1. `/scaffold-terraform us-east-1 agulaldi-react-app` generates `terraform/` from `.claude/skills/scaffold-terraform/template-spec.md`.
2. `cd terraform && terraform init`, then `/tf-plan` to review and `/tf-apply` to create the resources.
3. `/setup-gh-actions create` writes `.github/workflows/deploy.yml` from the Terraform outputs.
4. Push to `main`: GitHub Actions runs `npm ci`, the tests and `npm run build`, then syncs `build/` (not the repo root) to S3 and invalidates CloudFront.
5. `/deploy` does the same build and sync from this machine when needed. `/infra-status` and `/infra-audit` check the result.

## Conventions

- Only the contents of `build/` are ever uploaded to S3. Never sync the repository root.
- Hashed files in `build/static/` get a one-year immutable cache; everything else (including `index.html`) is `no-cache` so new deploys are picked up immediately.
- All AWS changes go through Terraform. Never change AWS resources by hand or with the AWS MCP server.
- `terraform apply` always applies a saved, reviewed plan (`/tf-apply`); `-auto-approve` and `terraform destroy` are blocked by a hook.
- The GitHub OIDC provider already exists in this AWS account (created by another project). Terraform must read it with a `data` source, never create a second one.
- This repo uses GitHub's immutable OIDC subject: `repo:agulaldi@129971097/my-react-app@1425706587:ref:refs/heads/main`. The deploy role trusts only that subject.
- Never commit `terraform.tfstate`, `.terraform/`, `*.tfplan`, `.claude/settings.local.json` or `.claude/deploy.log`.
